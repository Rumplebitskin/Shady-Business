Supabase setup SQL (run once in the SQL editor) 
create table if not exists sbr_scans (
  id bigint generated always as identity primary key,
  address text not null,
  ruleset text not null,
  slot bigint,
  score int,
  confidence real,
  result jsonb not null,
  created_at timestamptz default now()
);
create index if not exists sbr_scans_addr on sbr_scans(address, ruleset, created_at desc);
create table if not exists sbr_blocklist (
  address text primary key,
  reason text,
  added_at timestamptz default now()
);
alter table sbr_scans enable row level security;
alter table sbr_blocklist enable row level security;
create policy "read scans" on sbr_scans for select using (true);
-- 3.10: no public insert on sbr_scans (the page no longer writes there). If you ran older SQL, also run:
drop policy if exists "insert scans" on sbr_scans;
create policy "read blocklist" on sbr_blocklist for select using (true);
create table if not exists sbr_labels (
  address text primary key,
  name text,
  kind text check (kind in ('exchange','service','protocol','scam','defunct','gambling')),
  source text,
  verified_at date,
  added_at timestamptz default now()
);
alter table sbr_labels enable row level security;
create policy "read labels" on sbr_labels for select using (true);

How it works: each address is scanned, then SBR checks whether shady wallets score higher than legit ones (AUC: 100% = perfect split, 50% = coin flip). It then fits suggested factor weights with a pull toward the current ones. Weights change only the math. Saved evidence is re-scored instantly without new API calls.

Golden regression tests • frozen results that must keep scoring the same

      

    

    

      
      
      
      
      
      
      
    

    
A golden test freezes a scan’s evidence (factor values, slot, ruleset). Re-score runs today’s scoring math on that frozen evidence: it must give exactly the frozen score, so any change to weights or the formula shows up at once. Re-scan live scans the address again and lists which factors moved; new chain activity since the frozen slot is expected to move some, a ruleset change should be explained in the changelog. Stored in this browser; export the JSON to keep it or share it.
